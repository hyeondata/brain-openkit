# Brain OpenKit CLI implementation plan

> **For agentic workers:** Use test-driven development for the independent retrieval, provider, and CLI tasks; integrate and review the complete application before reporting completion.

**Goal:** Deliver a runnable read-only CLI for Korean/English Markdown retrieval, optional Laya reranking, and category/tag recommendations.

**Architecture:** A Python package owns vault reading and SQLite/BM25 retrieval. An HTTP decision provider translates bounded questions to Laya; workflows preserve source excerpts and explicit fallback state. The CLI offers text and JSON output and a small reproducible evaluation.

**Tech stack:** Python 3.11+, standard-library SQLite, argparse, urllib, and unittest. Laya runs as a separate optional server.

**Spec:** [Laya CLI design](../specs/2026-10-04-obsidian-laya-design.md).

## Global constraints

- Original independent implementation; reference upstream behavior, do not copy its implementation.
- Read vaults only. Exclude `.obsidian`, `.git`, caches, and symlinks; never modify source notes.
- Return exact UTF-8 source excerpts with 1-based inclusive line positions.
- Default search uses BM25 until model-quality evaluation supports enabling reranking; `--provider laya` opts in explicitly.
- Laya endpoint defaults to `http://127.0.0.1:8000`; require the `multilingual` route. Never fail over to a cloud provider automatically.
- Distinguish unavailable/invalid model results from completed inference; preserve provider-specific probabilities and usage.
- Reject truncated states/questions and collapsed options reported by Laya. Bound requests before transmission and document that exact token validation is returned by the server.
- Jev remains a future adapter. Generation and writes to notes remain outside this milestone.

## Review focus

1. Changed/deleted/unreadable notes must not survive as stale search evidence (retrieval tests).
2. Obsidian YAML, CRLF, fenced code, long lines, Korean text and symlinks must preserve citations or fail explicitly (vault tests).
3. Missing fields, NaN, wrong routing, authentication failures, redirects and truncation must not produce successful inference (provider tests).
4. Failed or partial reranking must retain a coherent BM25 ordering, with no mixed score scale (workflow tests).
5. Empty/malformed evaluation and taxonomy files must fail clearly without exposing credentials or claiming quality (CLI tests).
