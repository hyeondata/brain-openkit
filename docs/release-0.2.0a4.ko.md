# 릴리스 검증: 0.2.0a4

[English](release-0.2.0a4.md) | 한국어

이 문서는 아카이브의 동작 규약과 확인된 작업 소스 검증 결과를 기록합니다.
최종 배포 패키지 검사, CI 결과, 정확한 테스트 리비전은
[GitHub 프리릴리스](https://github.com/hyeondata/brain-openkit/releases/tag/v0.2.0a4)와
[검증 보고서](https://github.com/hyeondata/brain-openkit/releases/download/v0.2.0a4/verification-report.json)에서
확인하세요.

## 변경 사항

`0.2.0a4`는 지원되는 Claude Code·Codex CLI 콜백을 통해 선택적으로 사용할 수
있는 로컬 Markdown 대화 아카이브를 추가합니다. 아카이브는 기본적으로 꺼져
있습니다. 선택한 보관함에서 활성화하면 기록기가 `Inbox/Conversations/`의
세션 노트를 관리하도록 허용하게 되며, 다른 노트의 편집까지 허용하는 것은
아닙니다. 기존의 선별한 지식 저장 워크플로는 미리 보기·적용 방식을 유지합니다.

기록기는 모델이나 네트워크를 호출하지 않습니다. 대화에 표시되는 사용자·어시스턴트
텍스트를 보관하며, 명시적으로 활성화한 경우 대화 기록 안의 도구 출력도
포함합니다. 내부 추론, 삽입된 문맥, 도구 호출 인자, 바이너리 첨부 파일은
제외합니다. AI 요약을 생성하지 않습니다. 호스트의 일반적인 모델 사용과
원본 대화 로그 저장은 별도로 계속됩니다.

아카이브의 기본 용량 한도는 100 MiB이며, 세션 노트 하나의 한도는 2 MiB입니다.
한도에 도달하거나 아카이브가 편집되었거나 이력이 호환되지 않으면 기존 내용을
보존하고 이유를 보고합니다. 원자적 교체 중에는 일시적으로 최대 2 MiB가
추가로 필요할 수 있습니다. 보관 기간의 기본값은 0이며 자동 정리는 꺼져 있습니다.
명시적으로 허용한 정리만 오래되고 변경되지 않은 관리 대상 노트를 삭제할 수
있습니다. 이 한도는 Claude·Codex 자체 로그의 용량을 제한하거나 삭제하지 않습니다.

설정, 제한, 일시 중지·재개 동작과 호스트 설정은
[대화 아카이브 가이드](conversation-archive.ko.md)를 참고하세요.
[에이전트 통합 가이드](agent-integration.ko.md)는 검토 후 실행하는 스킬 8개와
선택 기능인 아카이브 훅을 구분합니다.

## 검증 상태

| 검증 근거 구분 | 현재 상태와 범위 |
| --- | --- |
| 코어·CLI 테스트 | 현재 작업 소스 기준으로 Python `3.11.13`과 `3.13.1`에서 각각 테스트 247개를 실행했습니다. 243개가 통과하고 플랫폼별 건너뛰기 4개가 있었으며 실패는 없었습니다. |
| Claude Code 콜백 | Claude Code `2.1.220`과 소스 플러그인에서 실제 네이티브 수집을 실행했습니다. OFF 상태에서는 보관함 파일이 생성되지 않았고, ON 상태에서는 메시지 2개를 저장했습니다. 같은 세션을 재개하자 반복된 텍스트를 포함한 메시지 4개가 같은 아카이브에 보존되었습니다. 최종 스냅샷을 다시 처리했을 때는 변경 없음이 반환되었습니다. `Stop`과 `SessionEnd` 이벤트가 관찰되었으며, 결과 스트림은 Stop 실행을 직접 보고했습니다. |
| Codex CLI 콜백 | CLI `0.149.0`과 플러그인 `0.2.0a4`에서 실제 네이티브 수집을 실행했습니다. OFF 상태에서는 보관함 파일이 생성되지 않았고, ON 상태에서는 메시지 2개를 저장했습니다. 같은 세션을 재개하자 같은 아카이브에 메시지 4개가 저장되었으며, Stop 스냅샷을 다시 처리했을 때는 변경 없음이 반환되었습니다. 이는 현재 작업 소스의 검사이며 최종 배포 패키지 검증은 아닙니다. |
| Codex Desktop | 자동 아카이브 동작은 검증하지 않았습니다. |
| 릴리스 패키징 | 릴리스 검증 보고서는 배포 리비전의 wheel·소스 빌드, 압축 파일 내용, 다른 위치로 옮긴 훅, 무결성 검사를 기록합니다. |
| 여러 플랫폼의 CI | 최종 릴리스 커밋의 결과는 릴리스 검증 보고서를 확인하세요. CLI 테스트 범위가 네이티브 호스트 훅의 검증 범위를 입증하지는 않습니다. |

네이티브 이벤트 감지, 플러그인 탐색, 대화 기록 파싱, 실제 자동 수집,
배포 패키지 실행은 각각 별개의 검증 근거입니다. 수동 대화 기록 가져오기가
성공했다고 해서 호스트가 훅을 호출했다는 사실이 입증되지는 않습니다.
두 CLI 검사 모두 합성 입력을 사용했으며, 수집된 메시지를 실제 입력과 응답에
대조하고 이전 메시지의 앞부분이 보존되는지도 확인했습니다. 각 검사에서는
일반 호스트 모델에 응답 3개를 요청했으며, 기록기 자체는 모델이나 네트워크를
호출하지 않습니다.

네이티브 검사는 작업 소스 플러그인을 사용했습니다. 대화 기록 읽기와 콜백
제한 시간의 최종 조정 후에는 기존 합성 입력을 로컬에서 다시 처리했으며,
새 호스트 응답을 생성하지 않았습니다. 보고서는 네이티브 실행과 최종 어댑터의
입력 재생 검사를 구분하며, 최종 SessionEnd 제한 시간이 3초임을 명시합니다.

릴리스 검증 보고서는 테스트한 호스트 버전, 콜백과 실행기의 출처, 명시적인
보관함 선택, 아카이브 내용, 소스 해시를 기록합니다.
수명주기 검사에는 기존 파일을 삭제하지 않는 비활성화, 호스트를 차단하지 않는
수집 차단·지연 처리, 보관 기간에 따른 정리 시 편집된 파일과 관리 대상이 아닌
파일의 보존도 포함됩니다. 최종 개수와 예외 사항은 이전 빌드가 아닌
실제로 테스트한 리비전을 기준으로 기록합니다.

## 배포와 과거 검증 근거

wheel은 수동 아카이브 명령을 포함한 Python CLI를 설치합니다.
호스트 콜백에는 전체 소스 배포본이나 태그 체크아웃이 필요하며,
`hooks/`, `scripts/`, `src/`, `skills/`와 호스트 manifest 파일을 함께
유지해야 합니다. PyPI와 공개 플러그인 디렉터리 배포는 이번 릴리스 범위에
포함되지 않습니다. 내려받은 배포 파일을 릴리스의 `SHA256SUMS`와 대조하세요.

[0.2.0a3 릴리스 보고서](release-0.2.0a3.ko.md), 날짜가 명시된 해당 릴리스의
[Claude 후속 검증](https://github.com/hyeondata/brain-openkit/releases/download/v0.2.0a3/claude-host-verification-2026-10-05.json),
[네이티브 Obsidian 앱 검사](obsidian-app-verification-2026-10-05.ko.md)는
각각의 범위에 대한 과거 검증 근거로 남습니다. 이 자료가 `0.2.0a4`의 아카이브
동작을 입증하지는 않습니다. 이전 Laya·Kev·Jev 검증 근거도 그대로 유지되며,
아카이브는 이 제공자들을 호출하지 않습니다.

## 한계

공개 검증 자료에는 합성한 일회용 대화와 보관함만 사용해야 합니다. 원본
호스트 로그, 인증정보, 계정 식별자, 개인 경로를 포함해서는 안 됩니다.
공개된 예제와 해시는 테스트한 아카이브 작업이 내용을 보존했음을 보여 줄 수
있지만, 연구 내용의 사실 정확성, 모델 품질 동등성, 비용 절감, 실제 운영
규모에서의 신뢰성을 입증하지는 않습니다.

첫 아카이브 버전은 바이너리 첨부 파일을 복사하거나 별도 외부 파일에 저장된
도구 출력을 읽지 않습니다. 대화 기록 압축이나 호스트 형식 변경으로 인해
기존 내용을 보존하기 위해 갱신이 차단될 수 있습니다. 세션 노트가 한도에
도달하면 호스트에서 새 세션을 시작해야 하며, 기록을 알리지 않고 잘라내거나
나누지 않습니다. 검증한 플랫폼과 남아 있는 호스트별 제한은 릴리스 검증
보고서를 확인하세요.
